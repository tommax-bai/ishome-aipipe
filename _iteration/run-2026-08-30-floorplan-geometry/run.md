# 真跑 · 户型图几何提取 · 2026-08-30 晚

> 目的：获客线「先出图」的**第一道门**——母版要的是坐标，先验证坐标提得出来。
> 用户裁决"先出图"（2026-08-30 晚），任务序列第一优先即本项，验收判据＝**画回原图能叠得上**。
> 纪律：本文所有数**逐字取自真跑**；失败的那次与不稳的那几处一并留档，不只留好看的。

## 一、输入与环境

| 项 | 值 |
|---|---|
| 样本 | `services/genpipe-worker/samples/floorplan-brochure-92sqm-3b2l1b.png`（同解析线那张，楼书级矢量渲染，1080×1466） |
| 勘测输入 | `../run-2026-08-30-floorplan-features/regions-{1,2,3}.json` 的 `survey` 段——**同一张图三次读的存档**，直接复用，本轮**一次模型都没调** |
| 跑法 | `uv run floorplan-geometry --image <图> --survey <存档> -o <目录>` |
| 耗时 | 每次约 **1.8s**（纯 Python + Pillow，无 numpy/OpenCV） |
| 产物 | `geometry-{1,2,3}.json`（几何）、`overlay-1.png`（核验叠图，验收看这张） |

**模型调用 0 次是本轮的要点之一**：几何提取本身不碰模型，勘测那一次的答案从存档来，
所以这条链路可以零成本、可复现地反复跑——调阈值、看叠图、再调，不必每轮付一次读图钱，
也不必担心两轮之间模型换了答案让改动的效果说不清。

## 二、结论：墙与洞不随模型动，房间归属随模型动

三次勘测存档喂进同一套代码：

| 项 | 结果 |
|---|---|
| **墙段** | **61 段，三次逐字完全相同**（JSON 序列化后逐字比对） |
| **洞** | 15 / 17 / 16 个，**14 个三次都有**；多出来的那几个全在房间归属有分歧的地方 |
| **自证覆盖率** | **97.3%**，三次相同（房间认领到的自由像素 ÷ 户型内部自由像素） |
| **图幅** | 归一化 `0.2657, 0.1951 → 0.7713, 0.6494`，三次相同 |
| **房间锚点** | 9 个里 3 个三次逐字同（小孩房、厨房、阳台）；其余最大漂移 0.018（约当图幅宽的 3.6%） |

**这条分界正是设计要的分界**：墙、洞、图幅、覆盖率全部从像素里算，模型碰不到它们
（import-linter 契约"几何提取纯确定性"把这件事锁死：本模块禁止依赖 `llm_client` 与 httpx）；
模型只做两件事——给房间起名、给区域生长下种。**它做的那两件事就是会动的那两件事。**

## 三、勘测框整体套准：把一次硬失败救了回来

**首版没有套准，第二份勘测存档直接响亮失败**：

```
几何提取不通过（fail loud，不降级往下游传）：
  - 这几个房间在墙网里落不到地：阳台——模型给的框与算出来的墙对不上
```

查下去：那次把阳台的框报成 y `0.65..0.69`，而图幅底线在 `0.649`——**整条报到了户型以外**。
这与分区读那一轮"勘测把阳台的框整体报低半个身位、裁出一张空白页"是同一个毛病的同一次现形
（交接文档追记六 §三）。

三次存档的框并集与算出来的图幅对比：

| 次 | 框并集 | 与图幅的差（左/上/右/下） |
|---|---|---|
| 1 | 0.27, 0.21 → 0.77, 0.65 | +0.004 / +0.015 / −0.001 / +0.001 |
| 2 | 0.27, 0.21 → 0.77, **0.69** | +0.004 / +0.015 / −0.001 / **+0.041** |
| 3 | 0.27, 0.22 → 0.77, 0.65 | +0.004 / +0.025 / −0.001 / +0.001 |

横向三次都只差千分之四，纵向下缘那次差了 0.041。**处置＝一次轴向线性映射**：
所有房间框的并集就是这套户型（每个房间都在户型里，户型也正是这些房间拼起来的），
所以那个并集应当与图幅重合；把它拉到图幅上，整体偏移就没了。套准后三次全部跑通，
阳台三次都落回阳台本身（锚点 `0.519, 0.626`，三次逐字同）。

**这条的成立前提写死了**：勘测得把房间报全，漏掉一个贴边的房间，并集就小于图幅、
映射会把所有框往外拉。三次存档都报全了九个房间，没有反例；**复看时点＝拿到第二批样本时**。

## 四、四次改判，都是真跑逼出来的（不是设计时想到的）

| 现象 | 根因 | 改法 |
|---|---|---|
| 一间卫生间认领了 8.7% 的户型（顺着门一路吃掉走廊与半个客厅） | 区域生长只按距离算代价，穿门与穿开阔地一样便宜 | 代价除以开口的通畅度——穿一道七成是墙的门要付四倍代价 |
| **51 个洞**，客厅正中央凭空几道门 | 判"这条线上有没有墙"时问的是原掩膜，**横穿过去的那条墙也答有**，于是每条线都显得贯穿整个图幅，线两端之间多出一堆断口 | 按轴向分开建两张墙体图，一条线只认与它同向的墙（截面宽度分：顺着竖墙横切截到的是墙厚，横切横墙截到的是长度） |
| 同一处墙报两遍、同一个洞报两遍，中间还夹出一条贯穿全图的窄缝 | 图幅四边与投票出来的外墙中心线**两条几乎重合的线都当线用**；两条线比探针半宽还近 | 图幅四边不作墙线（只留作产物里的 `plan_box`）；线间距门槛跟着探针半宽走 |
| 自证覆盖率 **102.1%** | 分子按格子面积算（格子从墙线量到墙线，把半条墙带算了进去），分母按自由像素算 | 两边都按像素——能超过 100% 的自证数只拦得住漏、拦不住多，等于半道闸 |

## 五、登记但不处置

1. **开阔处的房间边界不稳**：客厅 19.2% / 25.2% / 23.8%、玄关 4.7% / 3.5% / 3.5%——
   分歧全在 LDK 与走廊这类**本来就没有墙**的地方。有墙的房间（小孩房、厨房、阳台）三次逐字同。
   **不影响母版**（母版画的是墙），影响的是"房间标注该盖多大一块"。**时点＝房间标注要落到
   具体位置那一批**。
2. **阳台上半条被算进客厅**：阳台与客厅之间那道墙上的推拉门口子有 115px 宽，生长时几乎免费，
   而勘测给阳台的框只盖住下半条。后果是那道推拉门在"两侧属谁"这一关上被判成同一个房间、
   没进洞的清单。同第 1 条一批处置。
3. **只测过一张图**：跨图与脏图零数据。阈值虽按图幅的相对尺度取值，相对尺度本身也只在这一张上验过。
   **时点＝拿到第二批样本**（与解析线那几条技术债同批）。
4. **斜墙没测过**：轴对齐提取遇到斜墙会读成阶梯状。**时点＝拿到第一张带斜墙的样本时另立一项**。
5. **门窗不分**：本步只判洞在外墙还是内墙（确定性可判），门与窗的画法各家不同，要分得再走一步。
   **时点＝母版要画门扇与窗框那一批**（画法归 render2d）。

## 六、代码与守门

- 实现：`genpipe_worker/floorplan_geometry.py`（提取 + 核验叠图）、`floorplan_geometry_cli.py`（工具入口）；
- 模型：`genpipe_worker/models.py` 新增 `PlanWall` / `PlanOpening` / `RoomOutline` / `FloorplanGeometry`，
  **全部归一化坐标，没有任何绝对尺寸**（比例标定服务的是报告里的数字，出图不需要）；
- 守门：import-linter 新契约"几何提取纯确定性"（禁 `llm_client` / httpx / temporalio）；
  纵切形态白名单加两件；单测 `tests/test_floorplan_geometry.py` 九条，**用合成图不用样本图**——
  单测验的是判据本身（墙线找不找得到、断口算不算洞、房间落不落得下、自证不过会不会响亮失败），
  "这套阈值在那张图上跑得通"由本文留档。
- 全仓质量门：ruff / ruff format / import-linter / mypy / pytest **116 条全绿**。
