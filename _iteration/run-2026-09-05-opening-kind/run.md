> 起因：三维写实化换到线稿控制通道后，剩下的构件级失效是**门窗类型**（《失效清单-控制图通路-2026-09-04》

## 二、先说清今天产物里有什么可用事实

`openings[]` 每个洞有：轴向、墙线位置、沿墙起讫（洞宽）、`isOnOuterWall`、`connects`（两侧房间名）。
**没有**：所在墙段的引用（洞不与墙段相交，落在墙段之间的空隙里——交接文档 §四第 2 件）、门弧/窗线
（被第一步开运算整类抹掉了，掩膜里门窗过口长得一样）、与阳台/入户的邻接（只能从 `connects` 里的房间名间接看）。

可用事实逐条检过：

| 事实 | 能推出什么 | 数据说什么 |
|---|---|---|
| `isOnOuterWall` | 外墙洞＝窗或入户门；内墙洞＝门或过口 | 成立。但**外墙上窗与入户门靠它分不开**：138 入户门 94px，窗 58~277px；92 入户门 62px，窗 39~130px——宽度区间重叠 |
| 洞宽 | 想用"≥阈值且无门弧＝过口" | 不成立：92 过口 77px / 176px，门 50~77px，窗 39~130px——全部重叠。宽度不作判据 |
| `connects` 为空 | 两侧都不是房间＝管井/设备位，不是户内门窗 | 两图各一例（都是入户门旁的管井小门），全对 |
| `connects` 里的房间名 | 想用"连阳台＝推拉门" | 没用上：138 客厅↔阳台的洞靠跨洞线就判出来了；92 客厅↔阳台的推拉门口子根本不在洞清单里（两侧被判成同一间，8-30 run.md §五-2） |
| **原图像素里的门弧** | 有＝门；在外轮廓上＝入户门 | **最强的证据**：两图 9 个门弧全找到（92 一个门弧的圆心离产物里的断口半个门远，找不到，见 §五） |
| **原图像素里的跨洞平行线** | 外墙上 ≥3 条＝窗；内墙上 ≥2 条且无门弧＝推拉门 | 14 个窗 3~5 条，2 个推拉门 2、3 条，2 个过口 0 条 |
| 墙掩膜本身 | 断口被墙盖着＝墙角豁口；旁边贴着平行墙＝墙线错位 | 各一例，都是假洞，判成 `unknown` 并写明 |

`connects` 的两个坑一并记下（不是本轮的题）：走廊不是房间，被邻居认领——92 的走廊归了卫生间，小孩房门、主卧门
的 `connects` 里都写着"卫生间"；138 两个次卧同名并成一间，把餐厅走廊也吃了进去。8-30 就登记过（"开阔处的房间边界不稳"）。

## 五、登记但不处置

1. **92 主卧门给了 unknown**：门开在一截 ~67px 的短墙上（卫生间东墙延长线 y≈668），那截墙投不出墙线
   （票数 <16），产物里的断口是它南边 41px 那条线（y=709，卫生间底墙的延长线）上与门相交的空白。
   门弧圆心离断口有半个门远，四个候选够不着；只有门扇线穿过断口。**根因在几何提取（短墙不投票），
   不在类型推断**；门扇线单独作判据只有这一个正样本、且在假洞上认过一次家具边，先不升。
   时点＝拿到第三张图或短墙投票改了再看。
2. **推拉门规则只有两正两负**（138 厨房、客厅→阳台；92 两个过口）。92 的客厅→阳台推拉门不在洞清单里
   （两侧被判成同一间，8-30 §五-2 旧账），验不上。
3. **`connects` 在开阔处不可信**（走廊归邻居、同名房间并成一间），本轮只用它的"空/非空"，没用房间名。
4. **只测过两张图**：楼书矢量一张、彩色渲染一张。门弧灰度 138 是浅灰（138~178），92 是黑（≤140）；
   窗线 138 在白底墙带里、92 在纸面上——两种画法都过了，第三种（比如手绘、扫描）零数据。
5. **画法依赖比几何提取多一条**：几何只靠"墙是实心黑条、细线抹得掉"；类型还靠"门画弧、窗画平行线"。
   门画成斜线（有的图纸）或窗画成三线带缺口，今天会落到 unknown（不会错判）。

## 六、render3d 那边要改的点（由接手 render3d 的人做，本轮不碰）

1. `models.PlanOpening` 加 `kind: OpeningKind = "unknown"` 与 `kind_evidence: str = ""`——与本仓逐字对面
   （camelCase 别名 `kind` / `kindEvidence`）；`OpeningKind` 值域改成 `door | window | passage | entry-door | unknown`
   （今天是 `door | window | pass`，`pass` → `passage`）。`FloorplanGeometry` 加 `opening_kind_coverage_ratio`。
2. `mesh.opening_kind()`：先读 `opening.kind`，非 `unknown` 直接用；`entry-door` 按门起体（门高）；
   `unknown` 才退到 `HeightRules.outer_opening_kind / inner_opening_kind` 的猜法，**并计数**
   （场景包里 `opening_count_by_kind` 旁边加一个"按档位猜的"数，让猜了几个看得见）。
