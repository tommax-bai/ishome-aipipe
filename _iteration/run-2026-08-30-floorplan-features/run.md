> 目的：获客线第一步「特征能被推出来」的首次真模型验证——一张户型图 → 户型特征标记 + 依据。
> 纪律：本文所有输出与计数**逐字取自真跑**；被否的候选与失败形态一并留档，不只留好看的那次。

## 二、结论（三次同参同图，`reading-1/2/3.json`）

**特征标记逐字一致，三次全同**：

```
balcony_service ← 阳台区域图中画有洗衣机与柜体示意虚线框，表明设家政功能位
```

- `kitchen_u_shape` **三次都没出现**——三次的观察区都写"厨房为 L 形布局……未形成 U 形"，
  与实图一致（这条标记误报即判定失败，因为它会触发双人操作宽度那条规则）；
- `west_facing` / `bedroom_east_facing` **三次都没出现**，三次都进读不出区：模型读到指北针
  （"N 指向图上方"）也读到主卧在左下，但把"朝向"与"西晒"分开对待，判为图上无依据。
  **这是正确行为**——朝向缺席时相关规则不触发，不是降级（同交接文档坑 5）。
- 观察区 5 / 4 / 5 条，措辞逐次不同；读不出区三次都是同样三条（三条没成立的标记）。

**稳定性：产物层面三次完全一致，叙述层面（观察区条数与措辞）每次都变。**
下游只吃 `layoutFeatures`，所以对下游而言这次的稳定性是"三次同"。

**一处漂移如实记**：观察区对主卧朝向的说法三次不同（"朝西" / "朝南偏西" / "朝南偏西，非正东"）。
实图是主卧飘窗在下墙（N 向上即南向），**第一次的"朝西"是错的**。它没进标记（进的是观察区），
未造成危害，但说明：**朝向类判读现在还不可信**，闭集里那两条朝向标记就算将来要开，也得先有更硬的依据。

## 三、被否的候选与失败形态（本次真正的产出）

### 1. `qwen-vl-max`：唯一一次误报，且正好误报在最贵的那条

两次同参跑结果一致，两次都出：

```
kitchen_u_shape ← 厨房内部布局为三面围合，形成U形操作台     ← 与实图相反
```

同时把阳台判成"未标注家政功能位或设备"（漏报）。**误报 + 漏报同时发生**，正好是"误报比漏报贵"
那条纪律要防的形态 → 换模型。

### 2. `qwen3-vl-235b-a22b-instruct`：不误报，但理由是错的

零标记（安全），但观察区写"厨房内厨具沿三面墙布置，呈U形布局"（错），扣着不发的理由是
"图中无'U形厨房'文字标注"——**它把"图上没写这几个字"当成不判的理由**，而不是"图上画的不是 U 形"。
理由错的对答案不能算对，故不取。

### 3. 两步读（先逐房间清点图例、再判定）：试过，**撤回**

动机是模型在整图判读时漏掉阳台的设备位。清点那一步的原文逐字如下（节选）：

```
阳台｜下侧中央｜实线矩形狭长区域；内部：无任何图例（空白）｜上墙为推拉门（与客厅相连）……
指北针：……箭头指向图的右上方（即图纸右上方向为北）
```

**漏的照旧漏**（阳台仍是"无任何图例"），**还多错一处**（指北针实为正上方，被读成右上方）。
更糟的是它诱发了下面第 4 条。两步读＝两倍调用成本换负收益，撤回。

### 4. 「把闭集当逐条打勾的清单填」——比误报更贵，已立两道门禁

真跑里出现两次，一次在两步读、一次在单次读，形态是四条标记**全部出现**在 `layoutFeatures` 里，
依据写的是否定句：

```
kitchen_u_shape  ← 厨房内部台面为L形（左墙+上墙）……故非U形厨房
west_facing      ← ……'西晒'属主观感受描述，图上无'西晒'文字标注……无法判定
balcony_service  ← 阳台区域图中未画出家政柜、洗衣机位或生活功能示意……
```

匹配语义是**键存在即触发、下游根本不读依据**（契约 §一），所以这份产物一旦下发，
四条规则会带着"它不成立"的理由全部触发。落两道：

- **机检**（`layout_features._NEGATED_EVIDENCE_RE`）：依据是否定句即响亮失败，报出是哪个键；
- **prompt 第 0 条**：只放成立的标记，并给了一个用占位名写的错/对形态对照。

两道都上之后的三次跑全部干净。**注意先后**：只加 prompt 那一版仍然失败了一次（`EXIT=3`，
被机检拦下），这正是"prompt 是第一道不是门禁"的又一个样本。

### 5. 阳台设备位：漏了三次，靠一条通用读图约定救回来

模型在只被问阳台那一小块时，能逐个说出那两个虚线框和圆点（"虚线框内无任何标注或填充""实心黑点"），
但**不做功能推断**（原话："未作功能推断"）。补进 prompt 的是一条**通用**读图约定
（虚线框通常是家具/设备示意位，带点的小图形通常是地漏一类点位，图例本身就是图上可见的证据），
不是针对 `balcony_service` 的判定口径——判定口径该长在契约里，不该长在 prompt 里。

## 四、这次没解决的（留给下一批）

1. **图例级细节要真正读准，得按房间分区放大读**。本次三个模型在整图单次读时都漏过阳台设备位，
   只有把注意力限定到那一块才读得出。分区读需要先有房间定位（几何），属解析实现路径的选型，
   **时点写死＝拿到第二批样本（手机翻拍图与带尺寸标注图）那一批一起定**。
2. **朝向判读不可信**（见 §二 那处漂移）。闭集里 `west_facing` / `bedroom_east_facing` 两条
   现在拿不到可信输入，它们不触发是正确行为。
3. **稳定性只测了同一张图**。跨图稳定性、脏图门槛都还没有数据——脏图归第二步。

# 追记 · 逐条判定改造后的复跑 · 2026-08-30

> 上文是**旧形态**（模型直接产 `{标记名: 依据}`）的留痕，原文不改——它记的失败形态是本次改造的动因。
> 本节记改造后的复跑。**结论先说：新结构消掉了一整类失效，但在这张样本上丢了唯一那条真阳性。**

## 一、改了什么

**根因（用户判断）**：旧结构里"这条不成立"**没有位置**。模型面对四条候选的自然做法是逐条作答
（这本身是负责任的），结构不给它放"否"的地方，它只好把否定写进依据栏——于是有了上文 §三-4
那份"名字全在、依据全是否定句"的产物。**问题不在模型在结构**；靠"检查依据是不是否定句"去发现，
是在下游堵一个上游本不该产生的东西。

**改法**：给"成不成立"一个结构化的位置。模型输出层改成逐条判定
（`verdicts[] = {feature, holds, evidence}`），代码把 `holds=true` 的投影成 `layout_features`。
**下游契约一个字没动**——下发的仍是"只含成立的标记 + 依据"。判据是项目用过两次的招：
**结构性堵死 > 纪律禁止**（推导步看不见落点的值所以产不出数字；`min`/`max` 不在项名空间所以
"引单端"在语法上不存在）。这是第三次。

连带：名字越界校验**前移到判定层**且不论 `holds` 真假（判不成立的越界名同样是编造标记名）；
否定句那道闸**不删、语义改**——新定位是**自相矛盾检查**（`holds=true` 却给否定句依据）。

## 二、复跑（`verdicts-1/2/3.json`，同参同图三次）

**判定表三次完全一致，四条全判不成立**：

| 标记 | holds | 依据（第三次原话，三次措辞略有出入、判定无出入） |
|---|---|---|
| `balcony_service` | **false** | 阳台区域仅标注‘阳台’，未画出洗衣机、水池、储物柜等家政功能图例或文字说明 |
| `bedroom_east_facing` | false | 主卧位于户型左下角，根据指北针（N 向上），该侧为西南向；图中无‘主卧东向’文字标注 |
| `kitchen_u_shape` | false | 厨房图例显示为 L 形：北墙设灶台，东墙设冰箱位，西墙为操作台与水槽，无第三面连续操作台构成 U 形 |
| `west_facing` | false | 图中未标注‘该空间’具体指代哪个房间…‘西晒’属主观感受描述，图上无依据 |

**新结构按设计生效的部分**（都是 9 次真跑的观察，不是推理）：

- **"名字全在、依据全是否定句"这一类失效不再产生**——不是被拦下来，是没地方产生了。
  自相矛盾那道闸 9 次一次都没触发过；
- **零误报**：`kitchen_u_shape` 九次全判不成立，且理由每次都指得出 L 形的具体形态（哪面墙有什么）；
- **判定稳定**：三次 `holds` 全同，措辞小幅浮动；
- **没成立的那几条现在有数据了**——旧形态下它们要么缺席要么混在读不出区，现在每条都有 `holds` 与理由，
  这是判断"该改判据还是该改读图方式"的直接素材。

## 三、代价：丢了唯一那条真阳性（如实记）

`balcony_service` 在**旧结构下三次全中**（依据："阳台区域图中画有洗衣机与柜体示意虚线框"），
**新结构下九次全丢**。九次分三批，每批三次：初版判定 prompt、加"先看图再判/判成立要指得出图上的东西"、
把 `observations` 提到 `verdicts` 前面要求先逐房间描述再判——**三批都是 0/3**。

**丢的原因不是不肯推断，是没看见**：三次的观察区都逐房间列出了虚线家具框
（主卧的床与衣柜、小孩房的书桌、客厅的沙发茶几电视柜、玄关的鞋柜都点到了），唯独阳台写
"内部无任何家具或设备虚线框"。而实图上阳台端头画着两处虚线设备位与一个点位（人工核对过）。

**由此要如实说的一件事**：既然新结构下模型九次都说阳台是空的，那么旧结构下那三次"命中"，
到底是**看见了**那两个虚线框，还是从"阳台通常有洗衣机"**推出来**的？从输出看不出来。
**对的答案配不确定的理由，不能当成能力**——这条不该被记成"旧形态更准"。

**框架效应是真的**：旧 prompt 把任务框成"从图上找出成立的标记"（搜索），新 prompt 框成
"清单每条判一次"（核查）。搜索让模型去找证据，核查让它默认给否。这个差别 9:3 分得很干净，
不是噪声。但它**不构成回退理由**——旧框架的代价是那一整类否定句产物，而那是会让四条规则全触发的。

## 四、这次仍然没解决的

阳台设备位读不出来，**九次改 prompt 都没解决**，三种框架都没解决。这坐实了上文 §四-1 的判断：
**图例级细节要按房间分区放大读**，不是 prompt 能解决的问题。时点不变——拿到第二批样本那一批一起定。

# 追记二 · 分区读与朝向换算 · 2026-08-30 晚

> 用户批的两件事：**分区读**（先定位、再裁剪放大、再逐块读；按每个房间规划不按整体规划）与
> **朝向由代码换算不由模型判断**。上文两节是旧形态留痕，原文不改。

## 一、成本（先给数，这决定值不值）

| 项 | 旧（整图一次读） | 新（分区读） |
|---|---|---|
| 模型调用 | **1 次** | **11 次**＝勘测 1 + 房间 9 + 判定 1 |
| 耗时（同机同网关） | 约 20s | **35～39s**（逐房间那步并发上限 4） |

调用数 **11 倍**，耗时约 2 倍。买到什么见下面三节。

## 二、验收一：阳台设备位——**恢复命中 2/3**，且依据指得出图上的东西

三次跑的产物与**独立留档的近景原文**逐条对照（这正是上一轮那盆冷水的处置：
现在能分辨"看见了"还是"猜的"，因为近景是另一次调用、另一段原文，先于判定存在）：

| 次 | 勘测给阳台的框（纵向） | 近景读到什么 | 判定 |
|---|---|---|---|
| 1 | y 0.61–0.65（对） | "门洞右侧紧邻一个虚线框（内含一个黑点）…上方还有一个更小的虚线框…下方有一个小圆圈（地漏示意）" | **成立** |
| 2 | y 0.65–0.69（**偏低**） | "下方区域为空白，无虚线框、无小圆点/十字…" | 不成立 |
| 3 | y 0.61–0.65（对） | "开口右侧紧邻一个虚线框（设备或柜体示意），框内有两个小圆点…下方有一个小圆圈" | **成立** |

命中那两次的依据逐字是"阳台区域画有两个含黑点的虚线框（设备/插座示意位）及一个地漏小圆圈"
与"虚线框（设备或柜体示意），框内有两个小圆点…属家政/生活功能预留位"——**指的是图上真实画着的
东西**（人工核对过原图：阳台端头确有两处虚线设备位与一个点位），不是"阳台通常放洗衣机"式推断。

**漏的那次原因明确、可复核**：勘测把阳台的纵向位置整体报低了约半个身位，裁出来是图幅下方的
空白页，近景无从看见。**瓶颈是勘测框的坐标精度，不是模型看不清**。

## 三、验收二：没有引入新误报（但中途引入过一次，已处置）

- `kitchen_u_shape` **三次全判不成立**，且每次都指得出 L 形形态（哪面墙有什么），未被分区读的
  "看局部"带偏。
- `west_facing` **三次全判不成立**。

**中途确实引入过一次误报，记下来**：先前把"窗开在哪面墙"放在整图勘测那一步问，模型给没有窗的
卫生间报了一面**西窗**（人工核对：卫生间左侧是整段粗黑实线墙，无开口），这条假事实经确定性换算
变成"卫生间朝西"，判定那步据此判 `west_facing` **成立**——一次货真价实的误报。
**处置＝把窗墙这件事挪到近景去定**（近景是同一房间的放大图，看得最清），改完之后卫生间不再有
凭空的西窗，三次全干净。**教训写死：确定性换算不会把输入变准，只会把不准的输入变得像个确定结论**，
反而更容易被下游当真。

## 四、验收三：朝向换算可复现——**主卧三次同一个答案**

| 房间 | 窗在（近景读） | 换算 | 三次一致？ |
|---|---|---|---|
| 主卧 | bottom | **南** | **是（3/3）** |
| 次卧 | bottom | **南** | 是（3/3） |

两条都与原图相符（人工核对：主卧飘窗在下墙、次卧飘窗在下墙）。**次卧这条是被改造修正的**——
整图勘测原本把它报成右墙、换算成"朝东"，近景读对了。
其余房间三次之间有出入（厨房/小孩房/玄关有时报"没画窗"），**没画窗时不给朝向是正确行为**，
但也说明近景的窗墙识别本身还不稳，只是不再制造假朝向。

换算本身是算术，单测锁死了四个指北针方位 × 四条边的全表与"没有指北针退到上北下南"的约定。

## 五、试过并撤回：按整图尺寸算的"外扩下限"

针对第二节那个"框偏了裁出空白页"，试过给裁剪加一个按整图算的外扩下限（5%），
**三次真跑实测：阳台确实每次都裁对了、近景每次都看见了那两个虚线框**——但代价是每一块都带进了
邻居，窗墙归属跟着乱：主卧的飘窗三次里两次被报成"没画窗"，阳台被报出一面左墙的窗、
换算成"朝西"又催出一次 `west_facing` 误报。**误报比漏报贵，故撤回**，理由与数留在
`floorplan_regions` 的注释里。

**真正的瓶颈因此指得很明确：勘测框的坐标精度**。补外扩只是拿窗墙准确度换裁剪覆盖率，
两头不讨好。要根治得换一种定位办法（非模型的版面定位，或按图幅切片），
**时点＝拿到第二批样本（手机翻拍图与带尺寸标注图）那一批一起定**。
